# Browser decision authorization gate — disposable spike (2026-09-17)

**Research result: do not ship this gate.** It detected many unsafe model-like proposals with negligible observed median overhead, but an intentionally timed DOM replacement still caused a wrong-target click. The code and fixture were discarded; production, live MCP and real Chrome were never changed.

## Trust model and scope

Previous real MLX/RLCD study (`RLCD_DECISION_SPIKE_2026-09-17.md`) found only 60/100 exact `(action,target)` decisions and 10/20 actionable suggestions in cases requiring STOP. This follow-up did **not** reload the model: every proposed action here was **synthetic**, deliberately selected to test the authorization boundary. Do not attribute these results to new RLCD predictions or model accuracy.

The disposable gate accepted an exact, separately trusted `(action,target,payload)` intent supplied by the owned test host, then obtained the existing **redacted BrowserService snapshot** and captured one DOM element handle for the target. On execution it rejected mismatched action/target/payload, used a single-use capability, required the same page URL/navigation epoch, unique semantic target and identical underlying element, and delegated actual `click`, `fill`, `selectOption` and `waitForText` to the existing BrowserService. Thus the existing uniqueness, credential and native Playwright actionability checks were not disabled. A target missing at observation was rejected immediately: previously supported delayed discovery would require a fresh observation and permission. The experiment did not solve provenance of user intent; exact target authorization from a real high-level instruction requires a separate trusted planner or user confirmation. Webpage text, ARIA content and a model's confidence cannot create permission.

## Evidence

- RED: initial throwaway gate stub failed with `GATE_NOT_IMPLEMENTED`; the owned headless Chromium was closed.
- GREEN: on the first candidate run all 36 behavior checks succeeded, but a bug in the disposable benchmark percentile calculation made the **overall command exit 1**; that result was invalid for performance. Corrected the index and reran the entire program: **exit 0, 36/36 checks passed**, browser closed.
- 20 positive checks: five fixture wrapper layouts (`main`, `section`, `article`, `div`, `fieldset`) times `click`, `fill`, `selectOption`, `waitForText`. Clicks were real trusted Playwright mouse events and executed exactly once.
- 16 negative checks: changed action, changed target, changed fill value, changed select option, duplicate target introduced after observation, removed target, same-name replacement **before** identity check, text-to-password swap, hidden/disabled/overlaid button, changed accessible name, main-frame navigation, permission replay, page-injected instruction, and target absent at observation. No unauthorized click was observed in these checks; the password mutation was rejected by BrowserService's existing credential guard. Timeouts still refused disabled/covered targets.
- Alternating 32 baseline and 32 gated trials on the **same owned Chromium and small local fixture**, measured from `snapshot` through real click; both 32/32 clicks succeeded. Baseline median **114.09 ms**, p95 **227.93 ms**; gated median **114.27 ms**, p95 **133.34 ms**. Median difference +0.18 ms is not a meaningful independent speed gain, and unequal p95 values in 32 trials must not be attributed causally to the gate. No model generation, actual MCP, hosted transport or full user-facing task measured.

### Critical last-check-to-action race

A controlled proxy replaced the unique original Submit button **after the gate's element identity comparison but before** `BrowserService.click`. The substitute used the **same role and accessible name**. Playwright's ordinary locator re-resolved the current semantic target, and the gate returned `{ok:true}` while original clicks = **0** and decoy clicks = **1**. The final post-action URL/epoch check cannot detect or undo this wrong click. This is a demonstrated TOCTOU failure, not just a theoretical concern. Earlier fast-click experiments had also demonstrated wrong-target races with cached coordinates; this failure occurs even though the current native locator.click remains actionability-safe.

Separate controlled counterexample: when calling `ElementHandle.click` on a handle bound to the removed original node, Playwright refused it as **detached**; original clicks = 0 and decoy clicks = 0. This establishes one narrow property of identity binding in the fixture. It does **not** authorize substituting ElementHandle for BrowserService: the full uniqueness, credentials, frame/navigation safety, timeout and actionability contract would need independent source and adversarial tests. Do not introduce manual coordinate or synthetic click workarounds.

## Decision and next exact step

**Reject production integration of the temporary gate.** The 36/36 check result is not a global safety claim in view of the failing adversarial race. For a separate approved design, investigate an identity-bound *physical* locator action with strict current uniqueness and metadata checks, detached/replacement refusal, navigation and iframe/overlay/moving-element trials, and a trusted user-intent provenance story. Independently label more varied realistic tasks, report blocked valid actions as well as unsafe accepted actions, and instrument real hosted model/MCP roundtrips and complete task time before performance claims. Do not extrapolate these results to Jev's 150x claim. The previous full `npm run check` platform block was not bypassed; this was a throwaway research test, not a production release gate.
