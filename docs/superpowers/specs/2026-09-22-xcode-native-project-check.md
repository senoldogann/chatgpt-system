# Xcode-native project_check: bounded verification contract

Date: 2026-09-22
Status: Implemented on feature branch; deployment and real-repository acceptance require separate evidence.

An Xcode-only macOS repository must not be marked `UNAVAILABLE` merely because it has no `package.json` or `Package.swift`. Detection preserves the existing precedence: qualifying Node checks (including declared native scripts), then root SwiftPM, then Xcode. No caller-supplied scheme, project path, build flags, or command is accepted.

The Xcode fallback accepts exactly one regular, non-symlinked root `.xcodeproj`, a regular `project.pbxproj`, real `xcshareddata/xcschemes` directories, and exactly one regular shared `.xcscheme` with both `BuildAction` and `TestAction`. Ambiguous projects or schemes, untrusted paths, missing actions, and symbolic links produce no detected checks. Scheme contents are bounded to 1 MiB. Project and scheme names are constrained to safe path components. This is intentionally conservative; multi-project/workspace or multiple-scheme support requires a future explicitly reviewed configuration contract rather than selecting arbitrarily.

The two detected checks have fixed `xcodebuild` argv, shell disabled, a macOS destination, code signing disabled, warnings treated as errors, and bounded parallelism. `xcode:test` runs the shared scheme in Debug, with parallel testing disabled. `xcode:release-build` builds the same scheme in Release. `-quiet` reduces Xcode output against the existing bounded process-output budget. Both checks use the existing host-native execution lane and project-root path policy; native execution must be explicitly authorized through the current project lease plus the host-lane lease, and cannot fall back to Docker. Only xcodebuild checks have a default verification timeout of 600 seconds, and the host executor caps their caller-requested timeout at 600 seconds. Ordinary commands retain their existing configured timeout. These commands execute repository-controlled code as the logged-in macOS user, not in an OS sandbox.

The shared verification store persists the command identity, exit category, timestamps, exact HEAD and working-tree digest, stdout/stderr SHA-256 and byte counts, but not raw output. `PASS` requires successful execution of both checks on unchanged repository state; missing, failed, unavailable, or stale evidence blocks the unchanged typed `git_push` gate. This is build/test evidence, not code-signing, notarization, live macOS privacy/TCC, microphone, or provider acceptance. XCTest skips remain skips and must not be represented as tested functionality.
